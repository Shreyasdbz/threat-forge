# ThreatForge design critique 2: make the diagram the product

**Decision brief, not implementation.** Browser production build of `8fdb757`, Chromium in the repository-pinned Playwright image, 1440 × 900 CSS px, Daylight and Midnight, 1× and 2×. Captured 51 states in each configuration (204 screenshots). Measurements are CSS pixels from rendered geometry unless noted. The 2× crops make detail visible; they do not double the CSS sizes. Contrast uses computed foreground and sampled solid background, not anti-aliased edge pixels. [Contact sheet (defects 01–15)](design-critique-2-contact-sheet.png). Full screenshots, measurements and native-resolution crops are in the local, ignored `test-results/design-critique-2/` directory, with a backup and capture scripts in `~/tf-design-critique-2-evidence.tar`.

## Panel verdict

Four design lenses, not quotations or endorsements:

- **Apple HIG — control and predictability.** Give keyboard focus a home in every modal. Design alternate appearance and failure states as primary surfaces. Put recovery and export where the user expects, not where a developer found room.
- **Linear — hierarchy and density.** The title, task, and next action should be obvious before reading helper text. Reclaim space from repeated cards, decorative icons, verbose section labels, and redundant counts. Use list rows and disclosure for heavy feeds.
- **Figma — canvas first.** Workspace chrome must make sense at 2, 150 and 360 nodes. The editor should favor selection context and zoom/navigation over two sidebars full of unchanging content. Fit must fit; presentation is a view, not the hidden path to file export.
- **Vercel — semantic restraint.** Reuse one set of controls, one spacing rhythm, and one accent role. The product should feel capable at default settings without needing badges, colored icon tiles, quotes, or success confetti. The website should demonstrate a real architecture workflow before asking the visitor to believe a claim.

The issue is mostly not gradients or rounded cards. The editor is already largely square and neutral. It feels assembled from independently designed screens: a marketing-style empty canvas inside a diagram editor, tour icons on colored tiles, boxed inspector forms, a badge-like STRIDE list, and an assistant that narrates the same state in several places. **Keep** the real canvas, restrained selection accent, diagram presentation, native artifact portability, and explicit AI approval. Invest in locating actions, density and state ownership before any visual rebrand.

### Captured scope and gaps

- Workspace: public landing viewport, new-user changelog and welcome tour, no-document starter picker, opened cloud starter, new blank document, 2/150/360-node graphs, zoom detail and minimap; selection, Properties, Architecture, Threats (empty/list/detail), AI (no key, empty chat, actual partial streamed text from loopback SSE, pending proposal, applied); node and threat menus and keyboard focus; sequence and presentation of graph/sequence; early interview, flow editor and proposal.
- Controls: five Settings sections; command palette, keyboard shortcuts, AI chat picker, model menu, guided tours modal and focus escape; recovery inventory, missing/corrupt records and migration failure; report export menu; storage-unavailable and migration banners. A native browser clear confirmation was observed and dismissed in each profile; only its message, not its pixels, was captured. No generic toast system was found in the audited app surfaces; visual evidence covers status banners and inline alerts, not OS dialogs or every provider/error/custom-theme permutation.
- No device lab yet: narrow desktop, 200% browser zoom, mobile/pen, OS-specific Tauri chrome, native dialogs, screen readers, and authenticated AI were not audited in this pass. The scale and fault matrix below addresses them. The 360-node capture is a visual stress sample, not a benchmark or a substitute for larger interaction tests.

## Rhea token contract to try (not changes)

Stay on `components.json` style `base-rhea`, neutral base, semantic CSS variables, and Tabler as the default chrome icon library. Use the existing product accent for focus and primary verbs, not category decoration. Keep the diagram font separate from chrome: exported diagram legibility is a different contract.

| Area | Proposed tokens or rule |
|---|---|
| Type | Existing Figtree for chrome; reserve Outfit for one document/standalone heading style, not every section. UI ramp **12/16 500** metadata, **13/20 400** body, **13/20 600** labels, **16/22 600** panel titles, **20/28 600** dialog/page title. Marketing heading separately **36/44 650** max on desktop. No 11 px essential action copy. Inter for diagram content, monospaced only for identifiers and code. |
| Rhythm | **4, 8, 12, 16, 24, 32, 48 px**. Use 8 px row/action gap, 12–16 px panel gutters, 24 px section breaks, 24 px modal padding, 32 px larger composition breaks. Shared tab and toolbar baselines; no unmotivated one-off nudges. |
| Controls | **28 px** compact anchored menu/desktop icon-only control, **32 px** standard button/input, **36 px** ordinary list row, **40 px** touch-friendly/primary, **44 px minimum target for touch** where possible. No 16 px standalone targets; preserve a visible 2 px focus indicator with separation in both themes. |
| Borders and radii | One 1 px seam for docked regions; outline fields where interactive affordance requires it; no nested section borders by default. Use Rhea’s squared silhouette: **0 px** pane/grid edges, **4 px** controls and menus, **6 px** floating dialogs, virtually no full pills outside real tokens/status. Elevation only for detached surfaces; selection via an accent rule or tint, not several outlines. |
| Icons and states | **16 px** with **1.75 px** consistent strokes for actionable toolbar icons, **14 px** inline secondary, **20 px** for diagram or primary affordance where it carries meaning. No decorative header stars, repeated book tiles, emoji-like category marks, or colored backgrounds in every row. Pair semantic states with text; ≥4.5:1 text and ≥3:1 actionable boundaries/focus. Test default, hover, focus-visible, active, selected, disabled and pending in both palettes. |

## Deep functional and scale test plan (scope only)

**Build the corpus first.** Extend `e2e/fixtures/gen-large-model.mjs` with seed, schema and topology version. Generate 1k/2.5k/5k nodes with a chain/grid, clustered groups/layers, hub-and-spoke, and disconnected extremes. Include trust-boundary overlaps, sparse and dense edges, high fanout, long labels, Unicode/RTL, duplicate display names, mixed artifacts, findings/mitigations and sequences. Keep canonical fixture hashes and model counts; record seeds and retain only minimized repros. Run one 1k smoke for the PR lane and 2.5k/5k plus topology matrix in a scheduled serial suite, not every PR. Add 200% zoom and a narrow 1024×768 viewport on browser smoke.

| Stream | Workflow and oracle |
|---|---|
| Editor and persistence | Create/open/reopen each template; create/move/reparent, reconnect, style/group/layer/annotate, search/select by key and pointer, then save/reopen, compare canonical model and layout digests. Tab reorder, rename, pin, close/reopen, reload, stale manifest, browser suspend/resume, blocked reset, quota, corruption and competing writes; assert the explicitly selected document and revisions only change when expected. Fault-inject storage at read/write/migration boundaries. |
| Long session | Deterministic 500-action browser replay across 10 tabs with selection, geometry, preview, export and reload checkpoints, then ≥1,000 actions in scheduled runs. Track a reference state reducer, snapshot digest after each transaction, undo/redo through the retention limit, redo invalidation after divergence, tab isolation, bounded revision count and no monotonic retained-resource growth after repeated close/reopen cycles. The largest workloads should prefer API/setup fixtures and use real UI interactions for representative checkpoints, not drive 5,000 mouse clicks. |
| Analysis and output | Run STRIDE from empty/starter/large/edited states; edit mitigations, rerun and confirm preserved identity; filter, jump to findings and return to focus. Sequence create/link/reorder/delete/reopen; interview skip/resume/dependency rejection/apply/undo; presentation fit, SVG/PNG/Markdown/HTML command and artifact parity. Decode PNG, assert SVG bounds/labels, Markdown escaped literals and deterministic content, and import VM/native equivalents where supported. |
| AI and MCP | Replay deterministic local SSE for cancellation, disconnect, malformed tool feedback, conflicting targets, large proposals, partial apply/reject, stale baseline and one undo. At 1k and 5k use `src-tauri/tests/mcp_stdio.rs` with two sessions on dedicated fixtures: open, page reads, dry-run/batch, expected revision, conflict, undo/redo, screenshot, export and fresh process reopen. Assert page/call/response bounds and no write on preview, failed precondition or cancellation. No external provider or credentials in CI. |
| Schema parity and fuzz | Generate seeded valid models, hand-written ambiguous scalars and invalid mutations; run browser read/write/read and Rust read/write/read on shared fixtures, cross both readers after each write, and check canonical equality, opaque extension preservation, original files on failures, and authored errors. Include depth/size limits, duplicate IDs, malformed scalars, geometry extremes, dangling references, nulls, tags, CRLF/Unicode, and invalid UTF-8 on native reads. Persist minimized counterexamples as regression fixtures. |
| Native and access | Chrome Linux, plus built Tauri on Windows/macOS/Linux; test OS file picker cancellation, save/overwrite, webview bridge/menu shortcuts, external filesystem changes, scaling and clipboard. Use VoiceOver/NVDA representative paths, keyboard-only modal focus, reduced motion, high contrast, 1×/2×, and dark/light. Keep baseline count low: crop only changed panels and require human approval for pixel diffs. |

### Budget proposals and how to gate them

These are candidate starting SLOs, **not measurements of the current app**. Collect the first baseline on a documented, idle reference runner before making any wall-clock metric blocking. Measure warm and cold separately, take the median and p95 across repetitions, and keep browser/cache/device scale fixed. Keep frame traces and clearly separate artifact generation from disk/download I/O.

| Signal | Reference-runner p95 target, 1k / 5k | More reliable PR gate |
|---|---|---|
| Open/restore → interactive canvas | ≤1.5 s / ≤4 s | Count parse, migration, first model projection, and fit calls: no duplicate full projection on cold open. Benchmark 1k→5k with identical edge density against a linear-growth envelope; instrument operation counts, not a shared runner’s stopwatch. |
| Pan/zoom input → painted frame | ≤20 ms / ≤33 ms during a fixed 120-frame action | Zero file serialization/IndexedDB writes during pure pan; ≤1 visual update per frame; no full graph projection; bound mounted visible-detail nodes by viewport plus overscan once level-of-detail work lands. |
| Move, select or edit a single record | ≤50 ms / ≤100 ms until committed UI | No unrelated tab rerender or redo invalidation on pan; capped recomputation of adjacent edges/inspector and exact before/after state digest. Gate count of projected records after a local edit once incremental rendering exists. |
| Save click → bytes handed to adapter | ≤0.5 s / ≤1.5 s locally, exclude interactive picker | One serialization and one committed write per save; identical normalized bytes for unchanged open/save; one durable revision per autosave burst with unchanged retention. Benchmark actual OS flush separately. |
| Memory, refresh and recoverability | Report heap and peak DOM by scale; tune thresholds from baseline | Fixed store/revision caps and no leaked tab subscriptions, object URLs, or pending queues after disposal. Two independent model digests across reopen, no corruption or silent loss under injected errors. |

**Proposed sequence:** (1) fix focus, contrast, scale fit and export discoverability with targeted regressions; (2) introduce shared UI tokens and flatten launch/inspector/AI review with before-and-after crops; (3) land seeded corpus and deterministic operation-count gates; (4) use benchmark results to set timing gates and add native/long-session coverage. No product code or baselines for CI were changed by this critique.
